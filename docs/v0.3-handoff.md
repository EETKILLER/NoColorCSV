## 已实现

| 范围 | 当前行为 | 主要位置 |
| --- | --- | --- |
| 列符号 | `◆ ■ ▲ ● ◇ □ △ ○` 按从 1 开始的列号每 8 列循环；当前单元格边缘显示“数字 + 符号”，状态栏和提示保留文字列号 | `src/presentation.ts`、`src/extension.ts` |
| 符号开关 | `nocolorcsv.columnSymbols` 默认 `false`；关闭后恢复原有焦点标记，不留符号文字 | `package.json`、`src/extension.ts` |
| 无障碍预设 | `standard` 沿用 v0.2；`highContrast` 使用更明显的边框、默认开启符号并在提示中写明焦点范围；`screenReader` 默认关闭视觉焦点和符号，保留状态栏文字及“显示当前列信息”命令 | `src/presentation.ts`、`src/extension.ts` |
| 设置优先级 | 通过 VS Code `WorkspaceConfiguration.inspect()` 判断用户或工作区是否显式设置 `columnFocus`、`statusBar`、`columnSymbols`；显式值优先于预设默认值。删除单项设置后才重新继承预设 | `src/extension.ts`、`src/presentation.ts` |
| 文案与测试 | 英、中、日、韩、西五种 README、设置说明和运行时翻译已更新；新增符号、预设与装饰切换测试 | `README*.md`、`package.nls*.json`、`l10n/`、`src/test/` |

当前设计只在**当前单元格**的边缘显示“数字 + 符号”，同列其他可见单元格保留简短的焦点标记，以免每格重复文字。移动光标后，每一列都能获得按列号稳定计算的符号。若未来需要多个可见列同时常驻符号，应另设计不遮挡 CSV 的显示方式；这不是 v0.3.0 的现有行为。

## VS Code 手工验收

1. 在 VS Code 打开仓库，按 **F5** 启动“扩展开发宿主”。先打开 `examples/sample.csv`，确认状态栏、列聚焦、命令和跨行导航仍与 v0.2 一致。**该现有样例的表头只有 3 列，没有第 17 列。**
2. 在扩展开发宿主中新建临时 `wide.csv`，粘贴以下两行并保存。此文件只是验收数据，不要加入仓库：

   ```csv
   c1,c2,c3,c4,c5,c6,c7,c8,c9,c10,c11,c12,c13,c14,c15,c16,c17,c18,c19,c20,c21,c22,c23,c24
   v1,v2,v3,v4,v5,v6,v7,v8,v9,v10,v11,v12,v13,v14,v15,v16,v17,v18,v19,v20,v21,v22,v23,v24
   ```

3. 在扩展开发宿主的“设置”中搜索 `NoColorCSV`，开启 `Column Symbols`。将光标分别移到第二行的 `v1`、`v9`、`v17`。三列的符号都应为 `◆`，但状态栏和边缘文字必须分别显示列号 1、9、17。第 2 列应是 `■`；检查第 24 列仍有正确编号。关闭符号后，边缘和状态栏不应再有符号。
4. 依次切换 `Accessibility Preset` 的 `standard`、`highContrast`、`screenReader`。高对比度预设应有更明显的焦点边界；屏幕阅读器预设默认无视觉焦点和符号，状态栏与“显示当前列信息”仍能读出行、列、表头和值。将 `Column Symbols` 明确设为关闭后再选高对比度，确认显式关闭仍生效；删除这个单项设置后，确认重新采用预设默认值。
5. 验证引号内逗号、跨物理行字段、尾部空字段、无表头、空文件、滚动、自动换行及窄编辑器。切换到非 CSV 标签或关闭 CSV 后，标记应清除。移动光标时不应主动弹出消息；只有运行命令时才显示详情。
6. 用浅色、深色和高对比度主题，以及 200% 缩放检查文字和边界；用屏幕阅读器核对朗读。若字体缺少符号，仍必须能从文字列号识别列。记录 Windows、macOS、Linux 上可执行的键盘验证结果；未实际运行的平台标为“未验证”。
7. 验收前后比较临时 CSV 的字节或哈希，确认扩展没有改写文件。不要把 `wide.csv` 或构建产物放进提交。
