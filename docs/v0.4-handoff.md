# v0.4.0 发布交接

更新日期：2026-10-15。本文件记录 v0.4 的实现、验证方法与仍需补做的人工验收。详细规格位于工作区原有的 `docs/development/v0.4.md`；该目录由用户保留，未纳入本次版本提交。

## 交付范围

- **04-1 / 04-2**：`src/csv.ts` 在一次 CSV 扫描中保存字段 UTF-16 偏移和语法错误。`validateCsv` 使用同一解析结果检查列数。错误包括未闭合引号、闭合引号后的字符和未加引号字段中的双引号；列数不一致为警告。最多显示 200 个问题，超出时另显示文字提示。空文件无诊断，末尾换行不增加记录。
- **04-3**：活动 `.csv` 文档的诊断显示在 VS Code“问题”面板，来源为 `NoColorCSV`。编辑后 150 ms 防抖刷新；按文档版本丢弃过期结果。切换、关闭文档或关闭 `nocolorcsv.validation.enabled` 后清除诊断。
- **04-4**：保留四个导航命令 ID、默认键位及 `when` 条件。上下导航跳过目标列不存在或目标字段格式错误的逻辑记录；左右仅去相邻字段。导航从选择区活动端开始，成功后只保留一个光标。格式错误字段及边界给出文字原因；同一提示不会连续弹出。
- **04-5**：新增默认开启的校验设置；英语、简体中文、日语、韩语、西班牙语 README、设置描述资源与运行时翻译已同步。

扩展只读：不调用编辑或保存 API。半角逗号仍是唯一分隔符；CRLF、LF、单独 CR、BOM、字段内换行、转义双引号与空字段沿用原有语义。`package.json` 和 `package-lock.json` 版本均为 `0.4.0`，没有新增依赖。

## 自动验证

在仓库根目录运行 `npm run compile`、`npm test`、`git diff --check`、`npm audit --audit-level=high`。2026-10-15 的本地检查结果：编译通过、38 项测试通过、差异空白检查通过、审计报告 0 个高危及以上漏洞。测试覆盖合法与非法引号、UTF-16 范围、列数基准、诊断数量上限、编辑与关闭后的清理、导航跳过短行和坏字段、多光标以及不修改文本。CI 结果在发布后补记。

## VS Code 人工验收

1. 在 VS Code 打开仓库，按 **F5** 启动“扩展开发宿主”，打开 `examples/sample.csv`。检查原有状态栏、焦点标记、详情命令和四向快捷键。
2. 在开发宿主中新建临时 `validation.csv`，依次粘贴 `a,b\r\n1,"x,y"`、`a,b\n1,"x`、`a,b\n1,"x"z`、`a,b\n1,foo"bar`、`a,b\n1`（将 `\r\n`、`\n` 输入为实际换行）。打开 **视图 → 问题**，核对无错误、三种语法错误及列数警告。修复文本后问题应消失。
3. 将光标放在跨行带引号字段内，用上下命令确认按逻辑记录导航；检查短行、空字段、边界文字提示、选择区活动端和多光标收拢。关闭校验、切换非 CSV 标签、关闭 CSV 后，旧诊断应消失。
4. 在 Windows、macOS、Linux 可用的环境中检查默认按键与系统、输入法及常用扩展是否冲突。冲突时在 VS Code“键盘快捷方式”搜索 `NoColorCSV` 重绑定，并在命令面板复测。用屏幕阅读器读取“问题”面板中的完整错误文字；检查浅色、深色、高对比度主题和 200% 缩放。
5. 比较临时 CSV 验收前后的字节；只有用户手动编辑应改变内容。不要将临时 CSV 或编译产物加入提交。
